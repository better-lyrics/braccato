braccato makes it dead simple to show synced lyrics.

The lyrics renderer from Better Lyrics, one of the most used YouTube Music extensions, as a single custom element with no dependencies.

Package manager
$

Each syllable lights up as it is sung.

Import the element and its three stylesheets, point it at an audio or video element, and give it an array of lines. It follows that element's playback, and clicking a line seeks to it.

Autoscroll moves the nearest scrollable parent. To use a different one, set view.host = { getScrollElement: () => frame }, like this page does.

Pick a song

Or play your own

Or drop an audio file anywhere on this page.

Line synced, or not synced at all.

There is no mode to set. Leave out parts and whole lines light up. Leave out the times too and you get plain, unsynced lyrics.

How the built-in lyrics are timed

Two voices, and the one behind them.

Give a line an agent and the second singer's lines move to the other side. Background vocals show up smaller, under their line.

Translations stream in

These often arrive after the lyrics. Add them to a line at any time and they animate in. Changing the song or timing clears them.

Credits close the song

Pass songwriters and the last line hands over to who wrote it. The credits wait, dim, and brighten once the song ends. One CSS rule hides them.

A theme is a stylesheet.

Style the class names with plain CSS. Settings, like where the active line sits, go in blyrics-* comments in the same stylesheet, so there is no separate config. An empty theme resets everything.

The full API.

            

              Eleven properties, four attributes, four events, and the class names themes can use. The renderer guide covers each one in more depth.
            


            

              Reference section
              
              
              
              
              
              
              
            


            

              

                
Properties

                

                  You can set any of these before the element is in the document. They are all applied when it connects.
                

                

              

              

                
Attributes

                

                  Attributes set their property, but properties never update the attribute. Otherwise current-time would change in the DOM sixty times a second.
                

                

              

              

                
Events

                

                  All four bubble and cross shadow roots, so a listener outside your own components still hears them.
                

                

              

              

                
Class names

                

                  These are public API, so renaming one would be a breaking change. Import them from @braccato/core/constants instead of typing them.
                

                

              

              

                
Custom properties

                
The ones you will use most. variables.css has the full list.

                

              

              

                
Stylesheets

                

                  Load these like any package CSS. Without them the lines are still there, just unstyled.
                

                

                

                  The element works out the space the first and last lines need and sets --blyrics-padding-top and --blyrics-padding-bottom, but lyrics.css only uses the bottom one. Add the top one yourself, like this page does.
                

              

            


            
              Read the renderer guide
            
          


          

            
Light DOM, so your CSS reaches it.

            

              The element renders into its own children, not a shadow root, so your page's CSS reaches the lines and the package's @property registrations work. This page checks both when it loads.
            


            

              

                
HTML written before the script loads still works

                
The tag is in the HTML before the script defines it. Once the script loads, its source and theme attributes should still apply. Checked once, on load.

    One view per document
    
              
    
                Two views on one page share the theme <style>, scroll padding, settings and playback clock, so the second
                overrides the first. That is fine if both use the same theme. If the themes differ, both dispatch
                braccato:error with phase: "conflict", their status becomes
                "theme-conflict", and both keep rendering.
